# Contract: mapa de fontes canônicas

**Version**: 1.0.0  
**Baseline**: 2026-07-13  
**Coverage**: 34 IDs do [catálogo de features](feature-catalog.md)

## Regras de leitura

- Os caminhos são relativos à raiz do repositório e as seções são identificadas pelo cabeçalho, não por número de linha.
- `Owner` identifica quem pode escrever o estado autoritativo. `Contributor` apenas consulta contratos, emite commands ou reage a eventos.
- `GP-*` não possui dados nem cria ownership: cada fluxo converge owners existentes.
- `R-*`, `SAGA-*`, `INV-*`, `CA-*`, `BS-*`, `BE-*`, `BD-*`, `DB-*` e `G1–G8` referem-se aos identificadores ratificados nos documentos indicados. Quando não existe decisão específica, aplica-se a baseline `R-02…R-148` ratificada em `docs/99-decisoes/baseline-ratificada-2026-07-13.md`.
- Os aliases `C1…C12` e os três concerns seguem `docs/02-tecnico/12-context-map-e-blueprint.md`, § “Mapa módulo → contexto”.

## Verificação mínima deste contrato

Um consumidor deve falhar se qualquer ID do catálogo estiver ausente, se uma referência não existir, se um `GP-*` for declarado owner de escrita ou se um aggregate receber mais de um owner. A cobertura esperada é exatamente: 1 fundação + 12 contexts + 3 concerns + 1 validação + 1 operação + 16 golden paths = 34 IDs.
